# SpecLang Pi Agent Migration — Full Work Order

## Context

SpecLang is a meta-circular specification-driven multi-agent system where specs self-assemble into code. Currently, its Phase 1 runtime is designed to run as an OpenCode plugin. We are switching the runtime foundation from OpenCode to Pi Agent (github.com/earendil-works/pi).

This branch is `pi-agent-migration`. We are using OpenCode ONE LAST TIME to generate the migration artifacts, then switching everything to Pi.

## Pi Agent Architecture (Target State)

Pi Agent is a minimalist TypeScript coding agent harness:
- **SDK**: `createAgentSession()` → `AgentSession.prompt()` for programmatic agent control
- **Extensions**: TypeScript modules with `pi.registerTool()`, event interception (`onToolCall`, `onSessionEvent`), custom commands (`/mycommand`), hot-reload (`/reload`)
- **4 core tools**: read, edit, bash, glob — system prompt under 1000 tokens
- **RPC mode**: JSON protocol over stdio for external programmatic control
- **No Docker, no auth.json, no model catalog** — just npm install + API key

## New SpecLang on Pi Architecture

```
specs/ (440 files)              ← SOURCE OF TRUTH
  ↓ [speclangd — our inotify daemon using chokidar/fs.watch]
cascade event router            ← our TypeScript module
  ↓ dispatches to Pi sessions
Pi agent sessions (6 roles)     ← pi SDK createAgentSession()
  ↓ guard interceptor           ← Pi extension: pi.registerTool() + onToolCall
src/ (generated code)
  ↓ [pipeline on convergence]
build.yaml → test → commit
```
