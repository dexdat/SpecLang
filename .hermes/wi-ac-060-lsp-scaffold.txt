# AC-060: LSP Server Scaffold — basic language server for .spec.md files

## Goal
Create a basic Language Server Protocol (LSP) server for SpecLang spec files. Initial deliverable: server starts, handles initialize/shutdown, provides diagnostics for header validity and reference resolution on `.spec.md` files.

## Implementation
1. Read specs/headers.spec.md — understand header format and validation rules
2. Read specs/core.spec.md — understand reference format (@ref:)
3. Create `src/lsp/server.ts` — LSP server using `vscode-languageserver` package:
   - `initialize` handler: returns server capabilities (textDocumentSync: full, diagnostic provider)
   - `textDocument/didOpen`, `textDocument/didChange` handlers: trigger validation
   - `shutdown` + `exit` handlers
   - Validation function: parse spec header, check required fields (id, version, layer), validate @ref references against known spec index
   - Read index.json (generated by `speclang index`) for reference resolution
4. Create `src/lsp/index.ts` — export server
5. Create `bin/speclang-lsp` — CLI entry point that starts the LSP server on stdio
6. Create `tests/lsp/server.test.ts` — tests:
   - Server starts and responds to initialize with capabilities
   - Server validates a spec with valid header → no diagnostics
   - Server catches missing required fields (id, version, layer) → diagnostic warnings
   - Server responds to shutdown

## Constraints
- CRITICAL: Container has NO Node runtime. DO NOT run tests or install packages. Just WRITE files.
- Add `vscode-languageserver` and `vscode-languageserver-textdocument` to devDependencies in package.json
- Use TypeScript strictly — no `any` types
- Follow existing project patterns (explicit types, proper error handling)
