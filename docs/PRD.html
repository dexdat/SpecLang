What Is SpecLang?

SpecLang is a reactive multi-agent system where natural language specifications self-assemble into working code. Human writes specs. AI agents cascade — each owning their files at a specific depth in the dependency tree — until working, tested, type-safe code exists in any target language. Specs are the source of truth. Generated code is disposable.

Core Principles

1. Specs Are Source Code

Review specs, not generated code. Specs version in git — code regenerates on demand. Specs describe intent; code describes implementation. The test: take only specs/ to a new machine, run speclang build, get working code.

2. Universal Headers

Every file knows where it came from and what it depends on. YAML frontmatter with @ref: pointers create a deterministic dependency graph. No RAG, no probabilistic retrieval — explicit context by design.

3. Agent Ownership by Depth

Agents own files at specific depths in the dependency tree. North Star (depth 0) → Spec Writer (1-4) → Code Gen (5-6) → Test Writer (7-8). One agent per file. No conflicts.

4. Spanning Tree Cascade

Specs form a dependency tree. Changes cascade from root to leaves. The tree expands to whatever depth the system requires — no artificial layer limits. Convergence when no file changes for 30 seconds.

5. Context Window Advantage

Each agent owns one file and sees only its explicit dependencies. Working set = agent prompt + owned file + 2-4 dependencies. Always fits in context. Scales indefinitely — context is O(dependency depth), not O(codebase size).

6. Git Is Memory

Per-file commits with UUID-linked causality chains. Every change tracked to its origin. Git history provides full context — no separate memory bank needed.

7. Autonomous Agent Depth

Project maturity levels from POC to Enterprise determine spec depth requirements. At agent_support: agent_autonomous, specs carry enough information for agents to operate without human intervention.
