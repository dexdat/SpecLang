# Git Commits

Per-file commits for perfect traceability. Every change is tracked.

## Overview

```speclang
# @block:git/overview @kind:note
Every agent write = one git commit.

Benefits:
- Perfect cherry-pick capability
- Clear history of what changed
- Easy rollback per file
- Blame shows which agent did what
- Models can query history for context
```

---

## Per-File Commits

### @git/per-file

```speclang
# @block:git/per-file @kind:entity
CommitStrategy:
  when: after each agent finishes
  what: only the file(s) that agent wrote
  
  format:
    git commit --only <file> -m "speclang: {agent_summary} [parent:{parent_commit_hash}]"
    
  commit_hash_tracking:
    - Parent commit hash is known from trigger context
    - Current commit hash is generated by git after commit
    - Parent hash embedded in commit message
    - Optionally added to spec headers as caused_by
    
  example:
    git commit --only specs/auth.scl -m "speclang: added auth entities [parent:abc123def]"
    git commit --only generated/go/auth.go -m "speclang: generated auth handler [parent:def456ghi]"
    git commit --only tests/auth.test.spec.scl -m "speclang: added login tests [parent:ghi789jkl]"
```

### @git/commit-flow

```speclang
# @block:git/commit-flow @kind:diagram
```mermaid
sequenceDiagram
    A as Agent
    F as File
    G as Git
    
    A->>A: get parent commit hash (abc123def) from trigger
    A->>F: write specs/auth.scl with caused_by in header
    A->>A: generate summary with parent hash
    A->>G: commit --only specs/auth.scl -m "speclang: added auth entities [parent:abc123def]"
    G-->>A: commit_hash_1 (def456ghi)
    
    A->>A: get parent commit hash (def456ghi) from previous commit
    A->>F: write generated/go/auth.go
    A->>G: commit --only generated/go/auth.go -m "speclang: generated auth handler [parent:def456ghi]"
    G-->>A: commit_hash_2 (ghi789jkl)
```
```

## Commit Messages

### @git/messages

```speclang
# @block:git/messages @kind:entity
CommitMessage:
  format: speclang: {summary} [parent:{parent_commit_hash}]
  
  source: agent's output summary
  
  metadata_included:
    - parent_hash: commit hash that triggered this change
    - agent: agent role (spec-writer, code-gen, etc.)
    - timestamp: when change was made
    
  examples:
    - "speclang: added auth entities to specs/auth.scl [parent:abc123def]"
    - "speclang: expanded auth/login operation [parent:def456ghi]"
    - "speclang: generated handler.go from auth spec [parent:ghi789jkl]"
    - "speclang: added test for login failure case [parent:jkl012mno]"
    - "speclang: auto-split auth.spec.yaml into 3 parts [parent:mno345pqr]"
    
  generation:
    - Agent completes work
    - Generates summary of what it did
    - Extracts key phrase for commit message
    - Adds parent commit hash from trigger context
    - Commits with formatted message
```

## Commit Hash Linking and Causality Tracking

### @git/commit-hash-linking

```speclang
# @block:git/commit-hash-linking @kind:entity
CommitHashSystem:
  change_id: "Actual git commit hash (generated by git)"
  parent_change_id: "Commit hash that triggered this change"
  
  stored_in:
    - commit_message: "speclang: {summary} [parent:{parent_commit_hash}]"
    - spec_headers: "caused_by: @commit:{parent_commit_hash}"
    - sqlite: "changes table with chain relationships"
    
  generation:
    - Agent gets parent commit hash from trigger context
    - Makes changes and commits
    - Git generates commit hash for this change
    - Embeds parent hash in commit message
    - Adds caused_by to spec header if applicable
    
  example_commit_message:
    "speclang: added auth entities [parent:abc123def]"
    
  example_header:
    caused_by: "@commit:abc123def"
    # change_id not needed - file at this commit hash is the change
```

### @git/causality-chain

```speclang
# @block:git/causality-chain @kind:entity
CausalityChain:
  reconstruction: "Follow chain to understand flow"
  
  even_if: "commits are out of order"
  
  because: "headers contain full context"
  
  example_flow:
    - Change A (commit: abc123) triggers cascade
    - Agent 1 writes file X (commit: def456, parent: abc123)
    - Agent 2 writes file Y (commit: ghi789, parent: abc123)  
    - Agent 3 writes file Z (commit: jkl012, parent: def456)
    
  query:
    - "What caused this change?" → follow parent commit hash
    - "What changes did this cause?" → find children by parent commit hash
    - "Reconstruct cascade" → build tree from commit hash links
```

### @git/header-fields

```speclang
# @block:git/header-fields @kind:entity
CausalityHeaders:
  optional_fields:
    - caused_by: "@commit:{hash}"  # commit hash that triggered this change
    - change_id: "@commit:{hash}"  # this commit's hash (optional)
    - part_of: "@cascade:{id}"    # which cascade this belongs to
    
  usage:
    - Agents add these fields when writing specs
    - System can track relationships
    - Even if commits happen out of order
    
  example_header:
    # speclang-header lines:15
    id: @specs/auth
    version: 1.0.0
    layer: 2
    caused_by: "@commit:abc123def"
    # change_id optional - file at commit hash def456ghi is the change
    part_of: "@cascade:20250222-001"
    ...
```

## History Tool

### @git/tool

```speclang
# @block:git/tool @kind:entity
speclang_git_history:
  description: "Get git history for a file"
  
  params:
    path: String
    limit: Integer (default: 20)
    
  returns:
    commits:
      - hash: String
        message: String
        author: String (agent name)
        timestamp: Integer
        diff_summary: String
        
  usage:
    # Model asks "what changed in auth.scl?"

### @git/commit-hash-tool

```speclang
# @block:git/commit-hash-tool @kind:entity
speclang_git_by_commit:
  description: "Query git history by commit hash or causality chain"
  
  params:
    commit_hash: String (optional)  # specific commit hash
    parent_hash: String (optional)   # find children of this commit
    cascade_id: String (optional)    # find all changes in cascade
    
  returns:
    changes:
      - commit_hash: String
        parent_hash: String
        file: String
        message: String
        timestamp: Integer
        
  usage:
    # Find what caused a change
    result = speclang_git_by_commit(commit_hash="abc123def")
    
    # Find what changes a change caused
    result = speclang_git_by_commit(parent_hash="abc123def")
    
    # Reconstruct cascade
    result = speclang_git_by_commit(cascade_id="20250222-001")
```

## Blame

### @git/blame

```speclang
# @block:git/blame @kind:entity
GitBlame:
  description: "See which agent wrote each line, with commit hash context"
  
  tool:
    speclang_blame:
      params: { path, line_range? }
      returns:
        - line: Integer
          content: String
          commit: String
          author: String (agent name)
          timestamp: Integer
          parent_hash: String (extracted from commit message)
          
  commit_hash_extraction:
    - Parse commit message for "[parent:{parent_commit_hash}]"
    - Extract parent commit hash for causality tracking
    - Link to parent change in chain
    
  use_case:
    - "Who added this rate limiting logic?"
    - "When was this entity defined?"
    - "Which agent made this change?"
    - "What change caused this line?" (via parent commit hash)
    - "What other changes were part of same cascade?"
```

## Branch Strategy

### @git/branches

```speclang
# @block:git/branches @kind:entity
BranchStrategy:
  main:
    - converged, tested specs and code
    - always deployable
    
  feature/*:
    - active development
    - cascade in progress
    - not converged
    
  worktree/*:
    - isolated test versions
    - parallel testing
    
  merging:
    - only converged branches to main
    - each merge = one cascade completion
```
